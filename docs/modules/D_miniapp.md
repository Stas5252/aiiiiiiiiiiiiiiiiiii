# D. Кабинет (Mini App)

Цель: кабинет нельзя сломать или обойти запросом; заявки с лендинга доходят и не превращаются в спам.

Находки: `docs/audit/02_bot_miniapp.md` K2, V3, V13 (часть API), V14, V15, V16, V18, M1–M4, M12–M17; косметика из `docs/audit/00_summary.md` («0 мин» на 320 px, «1 сделок»).

Главное:
- K2 ограничение частоты и одноразовый токен формы лендинга; M3 удалённый лендинг не принимает POST. Потерю заявок на дедупе (K1) чинит модуль B в `pipeline.py` — добавьте со своей стороны сквозной тест «6 заявок от разных людей → 6 лидов».
- V3 права: удаление участников, каналы, пауза — только владелец.
- M1–M2 единый разбор параметров: неверный ввод → 400 в JSON, а не 500.
- V14 статус «Горячий» остаётся в открытых. V18 dev-режим слушает `127.0.0.1`, тело только `application/json`.
- M16–M17 CSP, `X-Frame-Options`, `initData` только из заголовка, ссылки только `http(s)`/`tg`.

Готово, когда: тесты `aiohttp` на каждую находку; проход всех экранов в браузере на 320 и 390 px без ошибок консоли и горизонтальной прокрутки, скриншоты в PR.
