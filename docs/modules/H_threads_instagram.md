## Этап 4.1 — что написано и как работает

### Слайды и анимация (коммит 69181ab)

| Файл | Что делает |
|---|---|
| `leadhunter/content/design.py` | Собирает страницу слайда из HTML и CSS: обложка, пункт с номером, слайд со снимком сайта, последний слайд с призывом и контактом. Слова в `*звёздочках*` рисуются контуром |
| `leadhunter/content/browser_render.py` | Открывает эти страницы в браузере без окна (Patchright) и снимает картинку. Сеть закрыта, JavaScript выключен, с диска читаются только шрифты, сама страница и разрешённые папки. `render_pages` — картинки, `render_motion` — кадры анимации |
| `leadhunter/content/shots.py` | Снимок сайта для слайда о кейсе. Открывает только ссылки из брифа и только адреса из интернета. Снимок хранится неделю, не больше двух на карусель |
| `leadhunter/content/fonts/` | Шрифты и их лицензии OFL. Попадают в пакет через `pyproject.toml` |
| `leadhunter/content/render.py` | Запасной рисовальщик на Pillow: цвета по умолчанию теперь чёрные, шрифты те же. У `Brand` новое поле `site` |
| `leadhunter/content/video.py` | `build_motion` — короткое видео из кадров анимации; `build_video` принимает кадры анимации для сцен ролика |
| `leadhunter/content/factory.py` | Карусель и обложку рисует браузер. Браузер не запустился — рисует Pillow, в карточке пометка «нарисовано упрощённо». Имя, @контакт и сайт для подписи слайдов берутся из брифа, если не заданы в `/brand` |
| `leadhunter/features.py`, кабинет | Новый выключатель `format_motion` — «Анимация обложек и роликов», по умолчанию включён |
| `leadhunter/miniapp/landing.py` | Надпись на кнопке страницы лид-магнита чёрная, если цвет акцента светлый |

В тестах браузер выключен (`tests/conftest.py`): слайды рисует Pillow. Настоящий браузер — только в тестах с меткой
`slide_browser`; таких тестов пока нет.

### Тексты без выдумок (коммит 18ba7b3)

- `leadhunter/content/generator.py`: в указаниях ИИ — правила честности. Факты об исполнителе только из брифа; цифры,
  статистику, результаты клиентов и отзывы не придумывать. Если по полю брифа «Кто вы» исполнитель работает один —
  писать «я», не «мы».
- `leadhunter/content/facts.py`: программа после ИИ сама ищет в тексте числа с единицами («70%», «3 дня», «втрое»,
  «7 из 10») и сверяет с числами из брифа. Чего в брифе нет — пишет в карточке «Проверьте перед публикацией».
  Ничего не вычёркивает и публикацию не запрещает. Список хранится в новой колонке `content_items.checks`.
- Сверка повторяется после каждой правки текста (`ContentFactory.recheck`).

### Версии для площадок (коммит 18ba7b3)

- У поста, карусели и ролика ИИ пишет отдельный текст для Threads. Программа ужимает его до 500 знаков по концу
  предложения и убирает хэштеги (`facts.fit_threads`). Хранится в новой колонке `content_items.threads_text`.
- Публикация в Threads берёт этот текст; остальные площадки — подпись с хэштегами (`compose_text(row, platform)`).
- Бот: в карточке блок «Threads (N из 500 знаков)», кнопка «✏️ Текст для Threads», кнопка «📦 Пакет» присылает
  два текста — для Threads и для Instagram — и обложку с анимацией файлом.
- Кабинет: в карточке материала тексты для Threads и Instagram с кнопкой «Скопировать» и блок «Проверьте перед публикацией».

### Этап 4.3 — публикация, комментарии, статистика, воронка

- публикация в Threads и Instagram через браузер по кнопке владельца;
- полезные посты с воронкой: пост → «напишите РАЗБОР» → бот видит комментарий, собирает досье на сайт автора,
  готовит ответ с фактами → владелец отправляет;
- ответы на комментарии под своими постами — черновики;
- раз в неделю разбор статистики: какие темы дали просмотры, ответы и заявки; следующий план строится от него;
- план на неделю из брифа: кейсы, ошибки сайтов в нишах клиентов, как идёт работа, цена, бесплатная проверка сайта.

Рассылку в личку незнакомым, одинаковые комментарии пачкой, обход капчи и блокировок, отправку без кнопки владельца.
Риск остаётся: Meta может ограничить аккаунт за автоматизацию.
