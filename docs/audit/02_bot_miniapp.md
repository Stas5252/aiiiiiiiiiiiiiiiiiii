# LeadHunter — проверка бота, кабинета (Mini App) и безопасности

**Как проверялось.** Python 3.12, `pip install -e ".[dev]"`, `pytest` → `211 passed`. Рабочий токен и рабочая база не использовались: бот гонялся через `Dispatcher.feed_update` с фиктивным токеном `123456:FAKE`, подменённой сессией aiogram и временной SQLite; кабинет — `python -m leadhunter.miniapp.dev 1 8080` на копии базы после `scripts/seed_dev.py`, плюс тот же сервер в «боевом» режиме (`dev_user_id=None`, подписанный `initData`) на порту 8081; браузер — Chrome, 390×844, touch. Код проекта не менялся.

**Оговорка про бота.** Запросы к настоящему Bot API были запрещены, поэтому ответы Telegram смоделированы в подменённой сессии: разбор HTML (`can't parse entities`), лимит 4096 символов на сообщение. Находки, которые опираются на эту модель, помечены «(модель TG)». Всё остальное — фактическое поведение кода проекта.

**Вне кода.** В присланном архиве лежит `.env` с действующим `BOT_TOKEN`. Если архив уходил куда-то кроме этой сессии — перевыпустите токен в @BotFather. `.gitignore` файл `.env` и `data/` исключает — здесь всё правильно.

Итого: **2 критичных, 19 важных, 17 мелочей**. Ложное срабатывание, которое я отбросил, — в конце.

- SQL-инъекции через фильтры и поиск нет (параметризованные запросы); поиск `%` и `<img` работает как текст.

- Тело больше 1 МБ → 413. Поле-ловушка `website` и пустой контакт → 400.
- Ключи интеграций через API отдаются только маской (кроме прокси, V4).
