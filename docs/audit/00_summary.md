# LeadHunter — сводный отчёт проверки

Проверяли четыре независимых прохода: координатор (чтение кода, кабинет в браузере, перепроверка главных находок) и три агента по областям. Рабочий `BOT_TOKEN` из архива не использовался, запросов к Telegram Bot API не было, `data/leads.db` не изменена, код проекта не правился.

## Итог

- Штатные тесты: `211 passed`.
- Найдено 95 замечаний в трёх областях: 7 критичных, 47 важных, 41 мелочь. Несколько пересекаются между областями (помечено ниже).
- Подробности с командами воспроизведения и фактическим выводом — в частях 1–3 этого файла.

## Самое заметное из важного

**Источники и конвейер**
- Freelance.ru пропускает премиум-карточки (по запросу «сайт» разобрано 4 из 25) и пишет «Гонорар: Гонорар» вместо суммы — `sources/freelance_ru.py:12,18`. Перепроверено.
- hh.ru: User-Agent по умолчанию в чёрном списке (HTTP 400), источник включён и шлёт владельцу алерты — `config.py:119-120`.
- Название чата попадает в текст для скоринга: в чате «Боты и сайты» любое сообщение получает 10/10 — `sources/telegram_chats.py:82`.
- Скоринг по префиксам: «бот» ловит «ботинки» и «ботокс», «ролик» — «роликовые коньки» — `scoring.py:8-11,48-52`.
- Спам-детект банит автора навсегда за три обычные реплики в трёх чатах за час — `pipeline.py:69-79`.
- SLA-пинг и follow-up помечаются отправленными, даже если Telegram вернул ошибку; после простоя уходит пачка пингов по старым лидам — `loops.py:28-29,44-45`, `db.py:184-190`.
- Порог `/threshold 6–7` молча убирает все лиды аудита сайтов и Яндекс.Карт (у них фиксированный балл 5 и 6) — `pipeline.py:124,143-144`.

**Бот, кабинет, безопасность**
- Владельцем становится первый, кто написал `/start`, если нет `OWNER_IDS` и база пустая. В вашем `.env` `OWNER_IDS` не задан — `bot/handlers.py:101-109`.
- Вышедший из рабочей группы сохраняет доступ к боту и кабинету навсегда — `bot/guard.py:27-28`.
- Любой участник команды может удалить коллегу через API кабинета (в боте это может только владелец) — `miniapp/server.py:250`.
- Пароль прокси виден открытым текстом в `/setup` и в `/api/settings` любому участнику — `integrations.py:46`.
- Токены Threads и Instagram попадают в лог (`httpx` на уровне INFO пишет URL с `access_token`) — `integrations.py:92,96`.
- Ключ, вставленный в две строки, бот возвращает эхом в чат в тексте ошибки — `integrations.py:114`.
- Кнопка «Горячий» в кабинете прячет лид из «Нужно взять» и «Открытые» — `miniapp/server.py:61-62`.
- Неверный цвет в `/brand` (`#zzzzzz`) ломает рендер всего контента — `bot/content.py:438-441`. Найдено двумя агентами.
- Dev-кабинет слушает `0.0.0.0` без подписи и по умолчанию открывает рабочую базу — `miniapp/dev.py:40`.
- Кабинет умирает молча, если порт занят или `cloudflared` упал после старта — `main.py:98-99`, `tunnel.py:47-51`.

**Контент и установка**
- В архиве все 97 текстовых файлов с CRLF и без бита исполнения: `install.sh` и `update.sh` не запускаются. Возможно, это след упаковки на Windows — проверьте в репозитории.
- Команда установки из README (`curl …/install.sh | bash`) отдаёт 404.
- `install.sh` падает без `curl` и там, где есть `systemctl`, но нет systemd (WSL, контейнер); `update.sh` от root без `sudo` не перезапускает службу.
- Идеи из `/plan` получают статус `scheduled`: планировщик пытается их опубликовать, автопилот их не видит — `bot/content.py:291`.
- Ошибка ИИ в автопилоте съедает день без сообщения владельцу — `content/scheduler.py:55,73-79`.
- После простоя все пропущенные слоты расписания выходят одной пачкой — `content/scheduler.py:19`.
- Упавшая сборка видео оставляет пустой `.mp4`, материал публикуется голым текстом — `content/factory.py:157`.
- Эмодзи на слайдах и в роликах — пустые квадраты — `content/render.py:8-12`.
- Правка лид-магнита через «Текст» не попадает в публикацию — `content/factory.py:41-43`.

## Находки координатора

- Заявки с лендинга (критичное № 3) — найдено независимо, скрипт воспроизведения: 6 заявок → `landing_leads` 6 строк, `leads` 2 строки.
- `/api/leads?limit=abc` → HTTP 500 простым текстом вместо 400 — `miniapp/server.py:75-76` (у агента это M1, 25 таких запросов).
- Кабинет без ИИ пишет «задайте OPENAI_API_KEY в .env», хотя ключи ставятся через `/setup` и поддержан Gemini; ручной формат «Заголовок | слайд» в кабинете не работает, только в боте.
- Кабинет в браузере (десктоп и 320/390 px): вкладки, карточка лида, «Беру», настройки работают; горизонтальной прокрутки и ошибок консоли на тестовых данных нет. На 320 px «0 мин» упирается в край карточки, в отчёте «1 сделок» без склонения.

## Что работает

- Kwork, Weblancer, Яндекс.Карты без API, аудит сайтов — живые запросы дают полные данные; лиды доходят до базы и кабинета.
- Конвейер: дедуп, игнор-листы, свежесть, правила, ИИ-ветка на заглушке, 200 одновременных лидов, гонка «Беру» (один победитель), миграция старой схемы.
- Подпись `initData`: все варианты подделки → 401, посторонний → 403 на всех 17 `/api/*`. SQL-инъекций, XSS, path traversal не найдено; CSRF в боевом режиме невозможен.
- Рендер без ИИ: карусель 1080×1350, ролик и мультик 1080×1920 со звуком, кириллица и длинные тексты не вылезают за кадр.
- Публикация на моках: ошибка одной площадки не отменяет остальные.
- Docker-образ собирается; с минимальным окружением бот стартует и корректно завершается по SIGINT.

## Что не проверено

- Настоящий Telegram (бот и Telethon-чаты), VK, Instagram, YouTube, официальные API Threads и Яндекса, Serper, настоящие LLM и Gemini — нет ключей, рабочий бот трогать нельзя. Проверено на моках.
- Threads и hh.ru с российского домашнего IP — машина проверки в дата-центре вне РФ.
- Браузерные источники с логином, настоящий `cloudflared`, systemd- и macOS-ветки установщика.
- Находки, зависящие от реакции Telegram (длина сообщения, разбор HTML), проверены на модели API и помечены в части 2.
